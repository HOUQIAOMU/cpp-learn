在联合体（union）中，所有成员共享同一块内存空间。在你的代码中，n、ch、m 都从同一个内存地址开始，只是它们解释这段内存的方式不同（类型不同）。

n 是 int（通常是4字节），m 是 short（通常是2字节），ch 是 char（1字节）。

为什么 m 和 n 看起来"始终相等"？
实际上它们不是"相等"，而是在你打印时，低位字节相同：

m 只读取了 n 的低2字节（因为是 short）

而你给 m 赋值时，修改的是 n 的低2字节

用你的数据逐步分析：
1. a.n = 0x40;
内存布局（小端序）：

text
地址： 0x03 0x02 0x01 0x00
数据： 0x00 0x00 0x00 0x40
n = 0x40 (完整4字节)

m = 0x40 (只读低2字节：0x0040)

ch = 0x40 = '@' (只读最低字节)

2. a.ch = '9'; (0x39)
内存布局变为：

text
地址： 0x03 0x02 0x01 0x00
数据： 0x00 0x00 0x00 0x39
n = 0x39

m = 0x39

ch = 0x39 = '9'

3. a.m = 0x2059;
内存布局：

text
地址： 0x03 0x02 0x01 0x00
数据： 0x00 0x00 0x20 0x59
n = 0x2059 (低2字节被覆盖)

m = 0x2059

ch = 0x59 = 'Y' (0x59是'Y'的ASCII码)

4. a.n = 0x3E25AD54;
内存布局：

text
地址： 0x03 0x02 0x01 0x00
数据： 0x3E 0x25 0xAD 0x54
n = 0x3E25AD54

m = 0xAD54 (只读低2字节)

ch = 0x54 = 'T' (只读最低字节)

关键点：
打印时 %hX 只打印 short 的值（2字节）

m 始终等于 n 的低2字节

当你修改 m 时，只修改了 n 的低2字节

当你修改 n 时，m 看到的是新的低2字节

可视化示例（最后一步）：
text
n = 0x3E25AD54
    高位字节     低位字节
    [3E][25][AD][54]
                    ^ ch 看到这里 = 0x54 = 'T'
                ^^^^^ m 看到这里 = 0xAD54
    ^^^^^^^^^^^^^^^^^ n 看到全部
所以不是它们"相等"，而是 m 始终是 n 的一个子集（在大多数小端序系统上）。
